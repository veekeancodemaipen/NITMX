# ชุดพิสูจน์โจทย์ AI ช่วยทบทวนธุรกรรม

28 กันยายน 2569 · เตรียมพร้อมใช้ ยังไม่ได้ติดต่อหรือทดลอง · [Problem statement](onchain-ai-opportunity.md)

## คำถามตัดสิน

มีขั้นตอนใดยังมีภาระมากหลังใช้เครื่องมือปัจจุบัน และวิธีเพิ่มช่วยลดภาระโดยไม่พลาดความเสี่ยงหรือส่งตรวจคนสุจริตมากขึ้นหรือไม่?

## สัมภาษณ์และเดินผ่านงานจริง

เสนอเริ่มจากผู้คัด alert 3 คน ผู้ทบทวนอาวุโส 2 คน และผู้ถือปัญหา/งบ 1 คน จากอย่างน้อย 2 องค์กรถ้าเข้าถึงได้ เป็นจำนวนเพื่อเรียนรู้ ไม่ใช่ตัวอย่างที่พิสูจน์ตลาดหรืออัตราผิดพลาด

1. ขอเดินผ่านเคสล่าสุดที่ใช้เวลามากและเคสปกติ ตั้งแต่รับ alert ถึงบันทึกผล
2. ขั้นตอนไหนใช้เวลาลงมือทำ ขั้นตอนไหนรอข้อมูลหรือผู้อนุมัติ?
3. ข้อมูลแต่ละส่วนอยู่ที่ใคร เครื่องมือเดิมเรียกใช้ได้แล้วหรือไม่?
4. ใช้ผลิตภัณฑ์/รุ่น/โมดูลใด เปิด AI/automation หรือยัง ถ้าไม่ใช้เพราะอะไร?
5. ปัญหาคือ false positive ข้อมูลไม่ครบ กฎตั้งไม่ตรง หรือขั้นตอนอนุมัติ?
6. เคสล่าสุดที่ส่งกลับมาแก้หรือสรุปผิดเกิดจากอะไร มีหลักฐานให้ตรวจได้ไหม?
7. ถ้าปรับกฎ แบบฟอร์ม หรือเปิดฟังก์ชันเดิม ปัญหาส่วนใดเหลือ?
8. ใครรับประโยชน์ ใครจ่าย ต้องเห็นผลอะไรจึงจัดคน/ข้อมูลเข้าทดลองต่อ?

คำตอบว่าน่าสนใจไม่ใช่คำยืนยันซื้อ ขอหลักฐานเป็น walkthrough บันทึกเวลา หรือแบบฟอร์มที่ตัดข้อมูลระบุตัวบุคคลตามที่องค์กรอนุญาต

## ใบงานหนึ่งเคส

| ช่อง | สิ่งที่บันทึก |
|---|---|
| case_id / sampling_reason | รหัสสมมติและเหตุที่เลือก |
| current_tool / version / enabled_features | baseline จริง รวม AI ที่ใช้อยู่ |
| alert_created_at / review_started_at / review_ended_at | แยกคิวจากเวลาลงมือทำ |
| input_sources / available_at | แหล่งและเวลาที่รู้ข้อมูลแต่ละส่วน |
| task_steps / active_minutes / wait_minutes | เวลาค้น ตรวจ เขียน ส่งต่อ รอ และแก้งาน |
| missing_context / source_access | ข้อมูลขาดและสิทธิที่จำเป็น |
| initial_decision / senior_review / disagreement | ผลแรก ผู้ทบทวน และจุดเห็นต่าง |
| confirmed_outcome / source / outcome_date | ผลยืนยันภายหลัง; ไม่ทราบต้องคงไม่ทราบ |
| user_delay / incorrect_restriction | ผลต่อผู้ใช้และข้อจำกัดที่ตรวจยืนยันว่าผิด |
| supported_facts / unsupported_claims | แหล่งรองรับและข้ออ้างเกินหลักฐาน |

หลักฐาน on-chain ควรระบุ network, tx hash, token contract ถ้ามี, จำนวน/หน่วย, เวลา และแหล่งตรวจ ไม่จับคู่คนด้วยชื่อคล้ายหรือยอดใกล้กัน รายการภายใน Exchange ต้องใช้บันทึกที่อนุญาต

## การเปรียบเทียบก่อนสร้างระบบเต็ม

เสนอเริ่ม 30 เคสย้อนหลังที่องค์กรอนุญาต มีทั้งเคสส่งตรวจ เคสปิดปกติ และยังไม่ทราบผล คงสัดส่วนจริงสำหรับตัววัดงาน; ชุดเคสยากที่เพิ่มต้องรายงานแยก ไม่ใช้คำนวณ precision ของ production

| แบบ | รายละเอียด |
|---|---|
| A วิธีปัจจุบัน | เครื่องมือและคุณสมบัติที่ใช้อยู่จริง |
| B ปรับวิธีเดิม | ตั้งค่ากฎ แบบฟอร์ม เชื่อมข้อมูล รวมคุณสมบัติผู้ขายที่มีสิทธิทดลอง |
| C วิธีเสนอ | ข้อมูลชุดเดียวกัน ให้ AI ช่วยงานที่ยังติด พร้อมแหล่งอ้างอิง/ช่องไม่ทราบ |

ถ้ายังทดลองโมดูลคู่แข่งไม่ได้ ให้ระบุว่าเทียบไม่ครบ ไม่สรุปว่าชนะคู่แข่ง จัดลำดับและผู้ทบทวนไม่ให้จำคำตอบเดิม ใช้ผู้ประเมินที่ไม่ทราบแหล่ง output เท่าที่ทำได้ แช่ข้อมูล ณ เวลาตัดสินใจ ไม่ใส่ผลสอบสวนภายหลังลง input แยกเคสปรับแนวทางจากเคสประเมิน

ทดลองย้อนหลังหรือ shadow mode ก่อน โดยไม่เปลี่ยนผลการตัดสินใจจริงของลูกค้า การจำกัด/ปล่อยธุรกรรมยังเป็นกระบวนการขององค์กร

## ตัววัดและเกณฑ์เสนอ

- เวลา: median/p90 นาทีลงมือทำ รวม review และ rework; แยกเวลารอและเวลารวม
- คุณภาพ: ข้อมูลผิด/ตกหล่น ข้ออ้างไม่มีหลักฐาน และผลผู้ทบทวนอาวุโส; ความเห็นตรงกันไม่เท่ากับถูกต้อง
- ความเสี่ยง: เคสควรส่งตรวจแต่พลาด และคนสุจริตถูกส่งตรวจ/จำกัดผิด ต้องมี label ยืนยัน; ไม่ทราบไม่เท่ากับสุจริต
- ผลปลายทาง: การหยุดส่งเงินต่อ/เงินคืนต้องมีผลติดตามแยก ไม่อนุมานจาก alert ที่ปิด
- ธุรกิจ: ประโยชน์สุทธิหลังค่าข้อมูล เชื่อมระบบ ตรวจผล และบริการ

เกณฑ์เสนอเพื่อหารือและล็อกก่อนเริ่ม ไม่ใช่มาตรฐานหรือผลสำเร็จ: ลด median เวลาลงมือทำอย่างน้อย 20% เทียบ B โดย p90 ไม่แย่ลง ไม่มีข้ออ้างสำคัญไร้หลักฐานในผลส่งมอบ และผู้ทบทวนไม่พบความผิดพลาดร้ายแรงเพิ่มในชุดทดลอง

30 เคสไม่พอยืนยันความปลอดภัยเมื่อเหตุร้ายพบยาก การไม่พบข้อผิดพลาดในชุดเล็กไม่พิสูจน์ว่าไม่มีความเสี่ยง ต้องใช้ baseline อัตราเหตุจริงกำหนดขนาดการประเมินถัดไปและรายงานความไม่แน่นอน

## เงื่อนไขหยุด/เปลี่ยนทาง

- ปัญหาเดิมถูกเครื่องมือปัจจุบันแก้แล้ว: หยุดโจทย์นี้
- B ได้ผลใกล้ C และถูกกว่าหรือดูแลง่ายกว่า: เลือก B ไม่ฝืนใช้ AI
- ไม่มีสิทธิข้อมูลหรือไม่มีผู้รับผลไปทำต่อ: ยังไม่ทดลองผลจริง
- คอขวดหลักคือรอภายนอก: ตรวจโจทย์ส่งต่อเมื่อมีหลักฐานและเจ้าภาพ
- คุณภาพลดลง/ภาระคนสุจริตเพิ่ม: แก้และประเมินใหม่ ไม่กลบด้วยความเร็ว
- ต้องทำเฉพาะรายทุกแห่ง: ประเมินธุรกิจบริการเชื่อมระบบแยกจาก SaaS
- ไม่มีผู้ถือปัญหา/งบหลังเห็นผล: ยังไม่ผ่าน validation ธุรกิจ

ประโยชน์แรงงานต่อเดือน = เคสเข้าเกณฑ์ × นาทีประหยัดสุทธิต่อเคส ÷ 60 × ต้นทุนแรงงานต่อชั่วโมง แล้วหักต้นทุนเพิ่มทั้งหมด ไม่รวมเงินที่อาจป้องกันได้จนมีผลติดตามแยกจากวิธีเดิม

**สถานะ:** พร้อมเก็บข้อมูลจริง แต่ยังไม่มีผู้ให้ข้อมูลและผลทดลอง ไม่ใช้เคสสมมติแทนการยืนยันปัญหา
